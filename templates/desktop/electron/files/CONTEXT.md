# Engineering rules — Electron desktop app

This is a TypeScript Electron app generated by smokeforge. Read this file before
changing code.

## Non-negotiables

- The renderer is untrusted. It must not access Node.js, Electron, filesystem,
  shell, network credentials, or raw IPC.
- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, and
  `webSecurity: true` are fixed defaults.
- Every renderer-to-main call goes through the typed preload API and the
  `ipc/handle` wrapper. Validate every payload with Zod in main.
- Never expose access tokens, refresh tokens, or secrets to the renderer.
  Tokens live in main-process memory and `safeStorage`.
- Keep services free of Electron imports where possible. Inject dependencies so
  domain logic remains unit-testable.
- Organize code by vertical feature slice, not by generic `handlers/` or
  `utils/` dumps.
- Use `feature:action` request channels and `feature:event` push channels.
- Return the shared `Result<T>` shape across IPC. Do not serialize raw errors.
- Use the `paths` module for userData, logs, temp, and resources. Do not scatter
  string paths.
- Do not put server-like data in Zustand. TanStack Query owns server state;
  Zustand owns local UI state only.
- Settings live in the typed JSON settings store. Durable local app data lives
  in SQLite through the main-process `LocalStore`. Never store tokens or secrets
  in either; use `safeStorage`.
- Do not run packaging or start long-running processes unless explicitly asked.

## Quality gate

```bash
make lint
make typecheck
make test
make build
```

A failing command blocks completion. Report actual output; never claim success
without fresh evidence. Use `make package-dir` to inspect the packaged app.
