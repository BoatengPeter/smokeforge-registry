# Engineering rules — Rust API

This project is a single-crate Axum API generated by smokeforge. Read this file
before changing code.

## Non-negotiables

- Organize modules by domain/use case, not by technical kind. Do not add
  `handlers/`, `services/`, or `models/` directories.
- Keep handlers thin; application logic belongs in services, infrastructure
  behind consumer-owned interfaces.
- Prefer private visibility. Use `pub(crate)` before `pub`.
- Use `Result` and `thiserror`; do not `unwrap()` in production paths.
- Propagate `tracing` spans and request-scoped context through async calls.
- Never hold locks across `.await`; move CPU-heavy work to `spawn_blocking`.
- Do not log secrets, passwords, tokens, or full request bodies.
- Use parameterized SQL only; never concatenate user input into queries.
- Return RFC 9457 `application/problem+json` errors.
- Keep `AppState` cheap to clone (`Arc`, pool handles only).
- Add unit tests beside modules and integration tests under `tests/`.
- Run `make check` before completion. Run `make test` with `-race`-equivalent
  runtime checks where concurrency changes.

## Quality gate

```bash
make fmt-check
make clippy
make test
make build
```

If PostgreSQL or auth is present, run `make db-up`, `make db-migrate`, and the
database-backed tests before reporting completion.

## Environment variables

- `src/config.rs` is the only place that reads `.env` or process environment variables.
- Every variable is typed, defaulted where safe, and validated at startup before the server binds.
- Never call `std::env::var` from handlers, services, repositories, or feature modules; inject `Config` or typed values.
- Secrets are server-only, never logged, never serialized into responses, and never placed in `.env.example`.
- New overlays add variables through the declarative registry `env` operation and config anchors, not ad hoc reads.

## Input validation

- Validate every untrusted boundary: request bodies, query parameters, path parameters, headers, cookies, uploads, environment values, and external responses.
- Reject invalid input before business logic, SQL, filesystem, network, or rendering work; return the app's typed validation error.
- Use allow-lists for enums, content types, sizes, sort fields, and redirect/origin values. Never concatenate untrusted input into SQL, shell commands, paths, or URLs.
- Validate at the closest boundary and keep domain invariants enforced by types. Client-side checks are UX only, never the security boundary.
- Validate content type and size for uploads, and validate the final stored object before marking it ready.
